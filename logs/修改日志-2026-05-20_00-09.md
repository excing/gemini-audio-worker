# 修改日志

日期: 2026-05-20

起始提交: `1d4da3e` (Improve voice mode UX and audio handling)

## 本次变更概览

本阶段围绕通话模式做了两条主线推进：
1. 通话内交互打磨——实时音频波形、主题/系统外观联动、长按录音体验改造、移动端触控修正。
2. 通话视频/投屏能力落地——按设计稿补齐摄像头模式和屏幕分享模式，抽出独立媒体服务模块，对接 Gemini Live `realtimeInput.video` 协议，并把权限/能力检查独立成方法。

## 详细修改

### 1. 实时音频波形可视化 (7536ab9)

- `audio-service.js` 中接入 Web Audio `AnalyserNode`：
  - `aiAnalyser` 挂在 `playbackGain` 之后，采集 AI 回放频谱。
  - `micAnalyser` 挂在麦克风 `source` 之后，采集用户输入频谱。
  - 均使用 `fftSize=64`、`smoothingTimeConstant=0.7`，权衡响应速度与抖动。
- 新增 `sampleWaveform(analyser, buffer, bins)`：把频域分段平均后做中心权重排序，让低频条目居中、高频条目分散两侧，视觉更自然。对外暴露 `getAiWaveform(bins)` / `getUserWaveform(bins)`。
- `index.html` 在通话模式启动时挂 RAF 循环 (`startWaveLoop`)，将波形数据写入 `aiWaveBars` / `userWaveBars`，并通过 `--wave-level` CSS 变量驱动 `.wave span` 高度/透明度。
- 离开通话模式或组件卸载时通过 `stopWaveLoop` 清理 RAF。

### 2. 主题初始化时序与中断按钮收敛 (812cb9f)

- 在 `<head>` 内联脚本中先于 Vue 渲染执行 `applyGeminiTheme`，避免首屏从默认浅色闪烁到深色。
- 删除 `mounted` 与 `saveThemeMode` 中重复的主题应用调用，依赖 `watch(themeMode)` 单点驱动。
- 用户说话期间禁用 AI 中断按钮 (`:disabled="showUserWave"`)，避免用户说话与手动打断逻辑冲突。

### 3. 动态浏览器外观 + 系统偏好联动 (6ade50c)

- 在 `<head>` 注入轻量自执行脚本，统一管理 `theme-color`、`msapplication-navbutton-color`、`apple-mobile-web-app-status-bar-style` 三个 meta：
  - 浅色: `#f9fafb` + status bar `default`。
  - 深色: `#09090B` + status bar `black-translucent`。
- `applyGeminiTheme(themeMode)` 解析 `system` 时按 `matchMedia('(prefers-color-scheme: dark)')` 决议，命中后写 `documentElement.dataset.theme`。
- 监听 `prefers-color-scheme` 变更：仅当当前 `themeMode === 'system'` 时跟随系统重绘 meta，避免覆盖用户显式选择。
- CSS 把深色背景从 `#1d1d1d` 调到 `#09090B` 拉高对比度，毛玻璃透明度同步调整；新增 `prefers-color-scheme: no-preference` 兜底块。

### 4. 长按录音：缓冲发送 + 15 秒上限 (d3a1e3c)

- `canSendAudioNow` 新增分支：长按、聊天模式、语音输入态下，即使 WS 尚未连通也允许 audio-service 持续产生 PCM，组件层把 payload 推入 `pendingClientPayloads`。
- 松手时 `handleHoldRelease → sendRecord` 追加 `realtimeInput.audioStreamEnd` 并触发 `sendRealtimeInputs`：会话就绪直接 flush；未连接则先 `connect()`，在 `setupComplete` 后由 session-manager 重放队列。
- 录音键内联展示剩余秒数与进度遮罩，使用 `requestAnimationFrame` 推动 `--hold-progress` CSS 变量，到 15 秒自动 `release({ reason: 'timeout' })` 并 toast 提示。
- 待发送队列由 `pendingTurnPayloads`（仅文本）+ `pendingClientPayloads`（音频）合并为统一的 `pendingClientPayloads`，audio-service 不再封装 `realtimeInput`，由组件按需组装。
- `src/session-manager.js` 把 `initialMessages` 由"turn 数组"改成"原样 realtimeInput payload 数组"，逐条 `JSON.stringify` 直发，去掉 `clientContent.turns` 包装层，简化协议假设。
- `audio-service.startMic` 内联 PCM 重采样与发送，`canSendAudioInput` 回调被移除，由组件用 `shouldSendAudio` 单点决定。

### 5. HoldRecord 组件抽离 (e93c836)

- 把长按按钮的状态机（按下 → precheck → 进度推进 → 松手/超时）封装成 `HoldRecord` 组件：
  - props: `modelValue`、`micStatus`、`maxMs`、`beforeStart`。
  - emits: `update:modelValue`、`release({ reason })`。
  - 自管 `holdProgress` 与 `holdRafId`，`beforeUnmount` 清理 RAF。
- 主组件相应删掉 `holdProgress` / `holdRafId` / `holdRemainingSec` / `startHoldProgress` 等状态与方法，只保留 `prepareHoldRecord` + `handleHoldRelease` 接口。

### 6. 移动端触控修正 (70f51fa)

- `HoldRecord` 的 `touchstart` / `touchend` / `touchcancel` 均加 `.prevent`，阻止 iOS Safari 长按弹出的系统菜单/选词菜单。
- `contextmenu.prevent` 阻断长按右键菜单。
- 样式新增 `touch-action:none; user-select:none; -webkit-user-select:none; -webkit-touch-callout:none`，避免移动端默认手势抢占。

### 7. 通话模式：视频 / 投屏 (本会话, 未单独提交)

- 设计稿同步更新 `docs/前端设计.md`，加入 Gemini Live 参考链接，并明确：
  - 视频画面位于 `call-stage` 的 wave 与 caption-overlay 之间，铺满；视频帧始终发送，不受静音按钮影响。
  - 投屏面板同样铺满，仅居中"退出投屏按钮"，不渲染屏幕画面；投屏帧始终发送。
- 新增 `public/media-service.js`，导出 `createMediaService({ onFrame, onSourceEnded })`：
  - `start('camera' | 'screen')`：内部先走 `checkAvailable`，再调 `getUserMedia` / `getDisplayMedia`；摄像头约束 `facingMode: 'user'`, `1280×720` 理想分辨率；屏幕分享仅取视频流。
  - 1 fps 抽帧：内部 `<video>` 元素作为捕获源，离屏 `<canvas>` 缩放到最大 1024 宽，输出 `image/jpeg`（quality 0.7）+ base64。
  - `setDisplayElement(el)`：把同一 `MediaStream` 绑到外部可见 `<video>`，用于摄像头模式预览。
  - track `ended` 事件触发 `onSourceEnded(source)`，覆盖用户在浏览器原生气泡里点"停止共享"的场景。
  - `checkAvailable(source)`：`isSecureContext` → `navigator.mediaDevices` → 对应 API 存在；摄像头额外用 `navigator.permissions.query({ name: 'camera' })` 提前识别 `denied`，并 `enumerateDevices` 校验 `videoinput` 存在。屏幕分享因 Permissions API 不覆盖 `display-capture`，仅做接口能力检查。
  - 异常按 `error.name` 抛出 `InsecureContextError` / `NotSupportedError` / `NotAllowedError` / `NotFoundError`，与 `audio-service.js` 对齐。
- `index.html` 通话面板接入：
  - 新增 `callMediaMode` (`'none' | 'video' | 'screen'`) 与 `mediaStarting` 守卫位；`startCallMedia` 改为 `.then().then().catch().finally()` 链式调用，`finally` 复位守卫位。
  - 抽出 `showMediaError(err, source)` 方法做错误 → toast 映射，复用 `NotAllowedError` / `SecurityError` / `PermissionDeniedError` 等别名，`AbortError`（屏幕选择器取消）静默处理。
  - 模板：`call-stage` 中插入 `.call-media` 层（z-index 1，位于 `.wave` 之上、`.caption-overlay` 之下）；视频模式展示镜像翻转的 `<video>`，投屏模式仅展示"退出投屏"按钮。
  - 视频/投屏按钮换装：根据 `callMediaMode` 切换 `screen-share` / `screen-share-off`、`video` / `video-off` 图标，并加 `active` 视觉态；`mediaStarting` 时禁用按钮防抖。
  - `onFrame` 回调直接通过 WS 发送 `{ realtimeInput: { video: { data, mimeType } } }`，按 Gemini Live 协议格式；不依赖静音模式。
  - `uiMode` watcher 与 `beforeUnmount` 中追加 `stopCallMedia` / `mediaService.destroy()`，确保退出通话或卸载时释放轨道。

## 风险提示

- `getDisplayMedia` 在 iOS Safari 仍不支持屏幕分享；当前依赖 `checkAvailable` 抛 `NotSupportedError`，提示文案已覆盖，但 iOS 用户实际无法体验该功能。
- `navigator.permissions.query({ name: 'camera' })` 在部分 Firefox / 较老浏览器不支持，代码已 `try/catch` 兜底，仍可走 `getUserMedia` 弹窗授权。
- 1 fps 抽帧使用 `setInterval` + `<canvas>.toDataURL('image/jpeg')`，在低端机上可能出现单帧编码 >1 秒、产生堆积；当前用 `capturing` 互斥位丢弃重入，但不会显式 backoff。
- 视频/投屏帧"始终发送"是按设计文档实现的，未跟静音逻辑联动；如果产品后续希望"静音时也停摄像头流量"，需要在 `onFrame` 处加门闸。
- 移动端长按触控的 `.prevent` 屏蔽默认手势同时也会屏蔽部分浏览器对辅助技术的手势；目前未观察到回归，但留意无障碍场景。
